# Phase 8 — 레이싱

> 참조: PROJECT.md §5-5, §6, §9-7

## 목표

다섯 번째이자 마지막 미니게임.
**나머지 넷을 합친 것보다 작업량이 크다. 가장 마지막에 구현.**

앞의 네 게임이 실기에서 안정적으로 돌아가는 것을 확인한 뒤에만 시작한다.

> **이 선행 조건을 지키지 않고 시작했다.** 실기가 아직 한 번도 없었고
> (`docs/playtest-1.md` `docs/playtest-2.md` `docs/playtest-final.md` 전부 미실시),
> 사용자 지시는 "나머지를 다 만들어 전체를 완성한 뒤 레이싱을 추가한다"였다.
> 실기를 기다리면 몇 주가 빈다는 판단이다.
> **대가**: 앞 4종이 실기에서 크게 흔들리면 레이싱도 같은 이유로 흔들린다.
> 흔들릴 만한 것(판정 임계값·기울기 감도)은 전부 `?tune=` 한 줄로 바뀌게 해뒀다.

## 작업 항목

### 렌더러 (`pseudo3d.js`)

- [x] **아웃런식 스캔라인 유사 3D** — 가로줄 단위 도로 렌더링. 연산이 가볍고 2.5D 질감이 난다
- [x] **Three.js 금지** (PROJECT.md §2) — canvas 2D의 `fill`·`fillRect`만 쓴다
- [x] 도로 세그먼트 자료구조 + 투영 계산
- [x] 도로 곡률 (커브) — 조각마다 서서히 붙고 서서히 풀린다
- [x] 언덕(y 오프셋)은 부하를 보고 도입 여부 결정 → **넣되 끌 수 있게** (`TUNE.HILLS` 0)
- [x] 카메라 — 플레이어 뒤 고정, 노면 높이를 따라 오르내린다
- [x] 스프라이트 깊이 정렬 (먼 것부터 그린다. 상한을 넘으면 먼 것부터 버린다)
- [x] 렌더 라인 수를 상수로 — `TUNE.DRAW_SEGS`. 주소로도 바꾼다 (`?tune=road.DRAW_SEGS:70`)
- [x] 배경 레이어 패럴랙스 (하늘·산) — 산은 톱니 한 줄, 채우기 한 번

### 게임

- [x] 조작 = **좌우 기울기(손목).** 지속 미세 조작. `tilt` 연속값 (폰이 25Hz로 보낸다)
- [x] 가속/브레이크는 자동 (5세에게 동시 조작은 무리)
- [x] 코스 데이터 포맷 정의 + 코스 1개 완성 → 2개
- [x] 충돌 — 도로 이탈 시 감속, 벽 충돌 시 짧은 감속. **게임오버 없음**
- [x] 랩 카운트 — 3랩. 전속력 63초, 시늉으로 64~82초 (한 판 90초)
- [x] NPC 주행 라인 + `npc.js` 러버밴딩 재사용 (`Racer`에 `lead` 옵션 하나만 더했다)
- [x] **쿠파 페이스메이커 + 마지막 20% 역전 연출 + 꼴등 없음**
- [x] 코인/아이템 배치 (선택) — 코인만. 24세그먼트마다, 바퀴마다 되살아난다

## 검증 방법

- [x] 렌더러를 게임 없이 단독 페이지로 먼저 띄우고 fps 오버레이로 라인 수·스프라이트 상한을
      잡은 뒤 게임 로직을 얹는다 → `tools/road-bench_1.html` (`/road`). **띄우는 것은 실기**
- [x] 기울기 감도를 3단계로 준비해 실기에서 고른다 → `racing.SENS_LEVEL` 0·1·2
- [x] 조카가 폰을 가슴이 아니라 핸들처럼 잡을 것 — **이 게임만 쥐는 법이 다르다.**
      캘리브레이션 안내 연출을 따로 만든다 → `calibHint`(TV) + `CALIB_TEXT`(폰)

브라우저에서 실제로 그려지는 것은 이번에 못 봤다 (Playwright MCP 연결 실패).
대신 도형 좌표를 받아 검사했다 — 멀수록 좁아지고, 아래로 수렴하고, 커브 방향으로
밀리고, 지평선(화면 한가운데) 위로 넘어가지 않는다. **색과 질감은 못 본 채로 남았다.**

## 리스크

- 이 단계에서 성능이 안 나오면 게임을 축소한다 (직선 코스 위주, NPC 수 감소). **프레임을 포기하지 않는다**
  - 축소하지 않고 줄일 수 있게 해뒀다: `road.DRAW_SEGS` · `road.DETAIL_SEGS` ·
    `road.HILLS` · `road.SPRITE_MAX` 넷 다 주소로 낮춘다
- 작업량이 크므로 렌더러 → 조작 → NPC → 코스 순으로 각각 동작 확인 후 다음으로 넘어간다
- 앞 4종이 실기 검증되지 않았으면 이 단계를 시작하지 않는다 → **지키지 않았다.** 위 목표 참고

## 만들면서 바꾼 것

**원심력을 미는 힘이 아니라 기준점을 옮기는 것으로 넣었다.** 기울기는 절대 위치
매핑이라(PROJECT.md 4장) 목표 위치로 끌어당기는 서보처럼 동작한다. 여기에 원심력을
"밀어내는 힘"(초당 0.5)으로 더하면 복원력(초당 2.2)에 통째로 먹혀 **커브가 공짜가 된다.**
처음 만든 판이 그랬고, 시늉을 돌려 보니 **가만히 있는 것이 가장 빠른 주행**이었다
(64.3초, 도로 밖 0%). 기준점을 옮기는 방식으로 바꾸니 커브에서 손목을 그쪽으로
기울이는 일이 생겼다. `test/games-test.js`의 마지막 두 항목이 그 회귀를 감시한다.
