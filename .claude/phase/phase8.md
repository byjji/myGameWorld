# Phase 8 — 레이싱

> 참조: PROJECT.md §5-5, §6, §9-7

## 목표

다섯 번째이자 마지막 미니게임.
**나머지 넷을 합친 것보다 작업량이 크다. 가장 마지막에 구현.**

앞의 네 게임이 실기에서 안정적으로 돌아가는 것을 확인한 뒤에만 시작한다.

## 산출물

- `js/games/racing.js`
- `js/pseudo3d.js` — 아웃런식 스캔라인 렌더러
- 코스 데이터 1~2개
- 카트 스프라이트 (주인공 + NPC 3종, 각도별 프레임)

## 작업 항목

### 렌더러 (`pseudo3d.js`)

- [ ] **아웃런식 스캔라인 유사 3D** — 가로줄 단위 도로 렌더링. 연산이 가볍고 2.5D 질감이 난다
- [ ] **Three.js 금지** (PROJECT.md §2)
- [ ] 도로 세그먼트 자료구조 + 투영 계산
- [ ] 도로 곡률 (커브)
- [ ] 언덕(y 오프셋)은 부하를 보고 도입 여부 결정
- [ ] 카메라 — 플레이어 뒤 고정, 커브에서 약간의 추종
- [ ] 스프라이트 깊이 정렬 (먼 세그먼트부터 그린다)
- [ ] 렌더 라인 수를 상수로 — phase1 예산에 맞춰 조절 가능하게
- [ ] 배경 레이어 패럴랙스 (하늘·산) — 저부하 방식으로

### 게임

- [ ] 조작 = **좌우 기울기(손목).** 지속 미세 조작. `tilt` 연속값 20~30Hz
- [ ] 가속/브레이크는 자동 (5세에게 동시 조작은 무리)
- [ ] 코스 데이터 포맷 정의 + 코스 1개 완성
- [ ] 충돌 — 도로 이탈 시 감속, 벽 충돌 시 짧은 감속. **게임오버 없음**
- [ ] 랩 카운트 — 한 판 90초 안에 끝나는 랩 수로 설정
- [ ] NPC 주행 라인 + `npc.js` 러버밴딩 재사용
- [ ] **쿠파 페이스메이커 + 마지막 20% 역전 연출 + 꼴등 없음**
- [ ] 코인/아이템 배치 (선택 — 부하 보고 결정)

## 완료 기준

- [ ] 30fps 유지 (렌더 라인 수를 낮춰서라도). 실기 미달 시 라인 수 하향으로 대응
- [ ] 조카가 손목만 기울여 코스를 완주한다
- [ ] 도로 이탈이 잦으면 도로 폭을 넓히거나 이탈 페널티를 줄인다 — **완주는 무조건 된다**
- [ ] 한 판 90초 이내
- [ ] 쿠파와 접전 후 조카가 이긴다
- [ ] 5종 전부가 룰렛에 등록되어 세션에서 뽑힌다

## 검증 방법

- 렌더러를 게임 없이 단독 페이지로 먼저 띄우고 fps 오버레이로 라인 수·스프라이트 상한을 잡은 뒤 게임 로직을 얹는다
- 기울기 감도를 3단계로 준비해 실기에서 고른다
- 조카가 폰을 가슴이 아니라 핸들처럼 잡을 것 — **이 게임만 쥐는 법이 다르다.** 캘리브레이션 안내 연출을 따로 만든다

## 리스크

- 이 단계에서 성능이 안 나오면 게임을 축소한다 (직선 코스 위주, NPC 수 감소). **프레임을 포기하지 않는다**
- 작업량이 크므로 렌더러 → 조작 → NPC → 코스 순으로 각각 동작 확인 후 다음으로 넘어간다
- 앞 4종이 실기 검증되지 않았으면 이 단계를 시작하지 않는다
