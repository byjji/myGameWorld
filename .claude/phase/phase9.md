# Phase 9 — 세션 통합 · 마무리

> 참조: PROJECT.md §7, §9 순서 배치, §10, §12

## 목표

미니게임 5종을 **하나의 세션**으로 묶는다. 총점·최종 우승·사운드·안정화.
"게임 5개가 있다"에서 "파티 한 판을 했다"로 넘어가는 단계.

> **순서 변경:** phase8(레이싱)보다 먼저 진행했다. 사용자 지시 —
> "나머지 모두 만들고 전체적으로 완성된 후 레이싱을 추가한다".
> 세션 구조는 게임 레지스트리 위에 얹혀 있어 레이싱이 나중에 들어와도 코드를 고칠 일이 없다.
> 등록만 하면 룰렛·보드·총점에 자동으로 낀다.

## 산출물

- `js/board.js` — 24칸 원형 보드. 판 결과를 칸 수로 환산하고 별을 센다
- 총점 / 최종 우승 화면 (`js/tv.js`의 `board` · `final`)
- 사운드 — **에셋이 아니라 합성이다** (`js/sfx.js`). 효과음 16종 + 화면별 BGM 5종
- `docs/adult-guide.md` — 어른용 한 장
- `docs/playtest-final.md` **(빈 양식. 조카 앞에서 채운다)**

## 작업 항목

### 세션 흐름

- [x] **점수 합산 구조 확정** — 5판 누적 단순 합산 vs 마리오파티식 보드 (PROJECT.md §12 미결정)
      *→ **마리오파티식 보드** (`js/board.js`, 24칸 원형). 단순 합산을 안 쓴 이유는
      게임마다 점수 단위가 달라서다 — 해머 90점과 줄넘기 12개를 그냥 더할 수 없다.
      보드가 "칸 수"라는 하나의 단위로 저울을 통일한다.
      **뒤로 가는 칸은 없다.** 쿠파 칸은 멈출 뿐, 별 칸은 지나가도 하나를 준다*
- [x] 총점 화면 + 최종 우승 연출
      *별 우선, 같으면 더 많이 간 쪽. 완전 동률은 공동 1등 — 꼴등 자리를 만들지 않는다.
      단 색이 밝으면 이름을 어두운 글자로 뒤집는다*
- [x] 게임 간 전환 흐름 — 결과 → 총점 갱신 → 룰렛 → 시연 → 캘리브레이션 → 카운트다운
      *`결과(6초) → 보드 → 선택 → 시연 → 캘리브레이션 → 카운트다운 → 플레이`가 5판 돌고 최종 화면.
      실제로 2판 세션을 끝까지 돌려 화면 전환을 확인했다*
- [x] **미니게임 순서 배치: 체력 부하 낮음 → 높음 → 낮음 → 높음 → 중간**
      *고정 순서로 박지 않았다 — 룰렛이 기본 방식이라 순서를 못 박으면 룰렛이 장식이 된다.
      대신 같은 효과를 규칙으로 만들었다: **첫 판은 부하 높은 게임을 뽑지 않고**,
      부하 높은 게임 다음에는 높은 게임이 안 나온다. 5판 세션 100번 시뮬레이션에서 위반 0회*
- [x] **줄넘기와 로프를 연달아 붙이지 않는다** (룰렛 체력 가중치로 이미 강제됨 — 재확인)
- [x] 세션 중단·재개 — 방이 끊겨도 재접속하면 이어지도록 (서버 재시작 시 소멸은 정상)
      *폰이 끊겨도 **45초 동안 명단에서 지우지 않는다.** 그 안에 돌아오면 점수도 보드 위 말도 그대로다.
      기다리다 멈추지는 않는다 — 끊긴 사람은 준비·캘리브레이션 판정에서 빠진다.
      전화·앱 전환이 실제로 자주 생기는 상황이라 이게 없으면 한 판이 통째로 날아간다*

### 사운드

- [x] **사운드 에셋 확보 방법 결정** (PROJECT.md §12 미결정)
      *→ **당분간 확보하지 않고 WebAudio로 합성한다** (`js/sfx.js`).
      에셋을 기다리면 피드백이 통째로 비고, 피드백이 없으면 조카는 인식 여부를 모른다.
      실제 에셋이 생기면 `play()` 안쪽만 갈아끼운다 — 부르는 쪽은 그대로다*
- [x] BGM — 화면별 1종, 루프
      *5종(로비·선택·플레이·보드·결과). 음량을 효과음보다 훨씬 낮게 뒀다 —
      BGM이 크면 판정 소리가 묻히고, 판정 소리가 묻히면 인식 여부를 모른다*
- [x] 효과음 — 동작 인식 / 성공 / 실패 / 코인 / 결과
      *16종. 종류마다 확실히 다르게 들려야 한다 — 조카는 화면을 보느라 소리를 곁눈으로 듣는다*
- [ ] TV 브라우저 오디오 자동재생 정책 확인 (사용자 제스처 필요 여부)
      *개발 PC 크롬에서는 `running`. **TV에서 막힐 경우의 대비는 만들어 뒀다** —
      TV가 소리를 못 내면 `fx` 메시지에 표시를 실어 보내고 폰이 대신 짧은 소리를 낸다.
      TV는 입력을 안 받아 제스처를 만들 수 없지만, 폰은 코드를 누르며 이미 만들었다.
      실제로 TV가 막히는지는 실기에서만 확인된다*
- [ ] 오디오 지연 측정 — 크면 효과음을 폰에서 재생하는 방안 검토
      *폰 재생 경로는 위 폴백으로 이미 있다. 지연 측정은 실기*

## 완료 기준

**전부 조카 앞에서만 확인된다.** 세션 구조는 다 만들었고, 개발 PC에서 2판 세션이
대기 → 선택 → 시연 → 캘리브레이션 → 카운트다운 → 플레이 → 결과 → 보드 → (반복) → 최종 우승까지
끊김 없이 돌았다. 양식은 `docs/playtest-final.md`.

- [ ] 5판 세션을 처음부터 끝까지 실기에서 완주
- [ ] 세션 전체 소요 시간이 조카의 집중 시간 안에 들어간다 (판당 90초 + 전환)
- [ ] 힘든 게임이 연속으로 나오지 않는다
- [ ] 조카가 "또 하자"고 한다 — **이 프로젝트의 실질적 완료 기준**
- [ ] 어른이 설명 없이 세션을 시작할 수 있다
