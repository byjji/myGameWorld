# Phase 3 — 공통 코어 (동작 판정 · 통신 · 화면 셸)

> 참조: PROJECT.md §4, §7, §8, §11

## 목표

미니게임 5종이 전부 올라탈 바닥을 만든다.
**동작 판정은 반드시 공통 모듈 하나.** 게임별로 흩어놓으면 임계값 튜닝 때 다섯 군데를 고치게 된다.

이 단계 끝에서 "폰으로 방에 들어가 캐릭터를 고르고, 점프하면 TV에서 반응한다"까지 된다. 게임은 아직 없다.

## 산출물

- `js/motion.js` — 동작 판정 공통 모듈 (점프 / 쳐올리기 / 스쿼트 / 좌우 기울기)
- `js/calib.js` — 3초 캘리브레이션
- `js/net.js` — WebSocket 클라이언트 (폰·TV 공용, 재접속 포함)
- `play/index.html` — 폰 단일 페이지 + 상태 머신 (라우팅 없음)
- `tv/index.html` — TV 셸 + 화면 전환 + 게임 루프
- `js/loop.js` — `deltaTime` 기반 게임 루프

## 작업 항목

### 동작 판정 모듈 (`motion.js`)

- [x] 센서 구독 — `devicemotion` / `deviceorientation`, iOS 권한 요청 흐름 포함
- [x] 저역 통과 필터로 손떨림 제거
- [x] **점프**: 세로축 가속도 스파이크 + **직전 0.3초 창에 합가속도 3m/s² 미만 구간(자유낙하) 존재**
- [x] **쳐올리기**: 세로축 스파이크 + 직전 자유낙하 구간 **없음**
- [x] 위 두 판정을 같은 링버퍼 위에서 처리 (스파이크 시점 기준 과거 0.3초 조회)
- [x] **스쿼트**: 자이로 pitch 왕복 1사이클(내려감 → 올라옴). 세로 가속도를 보조 신호로 병행
- [x] **좌우 기울기**: roll 각도 → 레인 절대 위치 매핑. **임계 10~12도**. 스텝 스파이크 감지 방식 채택 안 함
- [x] 중복 발화 방지 쿨다운
- [x] 세기(`p`, 0~1) 산출
- [x] 임계값을 **한 곳의 상수 테이블**로 모아둔다 (플레이테스트에서 계속 만질 값)
- [x] 판정기는 이벤트를 emit하는 형태 — 게임 로직이 입력 소스에 의존하지 않게 (PROJECT.md §11)
- [x] 디버그 오버레이 — 실시간 센서 파형 + 판정 발화 시점 표시 (튜닝에 필수)

### 캘리브레이션 (`calib.js`)

- [x] 접속 플레이어 목록 + 접속 시 캐릭터 등장 연출
- [x] 캐릭터 선택 화면 — L모자 / 마리오 / 루이지 / 공주 / 쿠파 / 키노피오
- [x] 동작 시연 화면 — 글자 대신 캐릭터가 해당 동작을 3초 반복. 텍스트 설명은 어른용으로 작게
- [x] 카운트다운 3-2-1-GO
- [x] 화면 전환 상태 머신 (대기 → 캐릭터 → 시연 → 카운트다운 → 플레이 → 결과)
- [x] 게임 루프 — **`deltaTime` 기반.** 30fps 기준으로 설계, 프레임 수 전제 금지

- [x] 렌더링 수치는 전부 `js/config.js` 참조. 게임 코드에 숫자를 박지 않는다
- [x] 미니게임 인터페이스 정의 — `init / update(dt) / render(ctx) / onMotion(e) / getScore()`

## 완료 기준

아래 네 항목은 **릴레이 서버(phase2)와 실제 폰**이 있어야 확인된다. 코드는 준비됐고 확인만 남았다.

- [ ] 폰에서 코드 입력 → TV에 캐릭터 등장까지 실기에서 동작
      *phase2 릴레이 서버를 로컬에 띄우고 실제 WebSocket으로 통과 —
      TV가 코드 5235 표시 → 폰 키패드 입력 → 캐릭터 선택 → 준비 완료 → TV가 캘리브레이션으로 넘어감.
      개발 배선(BroadcastChannel)이 아니라 진짜 서버를 거친 경로다. 실기(조카 집 TV·실제 폰)만 남음*
- [ ] 캘리브레이션 후 점프/스쿼트/기울기가 TV 디버그 화면에 실시간 반영
      *합성 센서로 통과. 실제 센서 확인 남음*
- [ ] 점프와 쳐올리기가 서로 오인식되지 않는다 (각 20회 시도, 오인식 2회 이하)
      *`test/motion-test.js`에서 각 20회 오인식 0. 실기 확인 남음*
- [ ] 폰 화면을 보지 않고도 진동만으로 인식 여부를 알 수 있다
      *데스크톱에는 진동이 없다. 실기 전용 항목*
- [x] 미니게임 하나를 붙였다 뗐다 해도 셸 코드를 안 고쳐도 된다
      *`js/games/debug.js`를 레지스트리로만 붙여 확인*

|---|---|
| `js/devlink.js` | `?dev=1`일 때 BroadcastChannel로 TV와 폰을 잇는다. 릴레이 서버 대역 |
| `js/devsensor.js` | 키보드로 센서를 흉내낸다. J=점프 P=쳐올리기 S=스쿼트 ←→=기울이기 |
| `dev/pair.html` | TV와 폰을 한 탭 안에 나란히 띄운다. 브라우저가 백그라운드 탭을 늦추기 때문에 필요 |

셋 다 `?dev=1`에서만 동작한다. 배포본 흐름에는 들어가지 않는다.
PROJECT.md 1장의 "오프라인 모드를 만들지 않는다"는 제품 결정이고, 이건 개발 중에만 쓰는 배선이다.

## 검증 방법

- TV에 판정 디버그 오버레이를 띄우고 점프/쳐올리기/스쿼트를 각 20회씩 수행, 오인식 횟수 기록
- 어른이 먼저 테스트한 뒤 조카에게 폰을 쥐어보게 한다 — **쥐는 각도가 어른과 다르다.** 임계값에 반영
- 폰 잠금·전화 수신·앱 전환 후 복귀 시 재접속 확인

## 리스크

- iOS는 센서 접근에 사용자 제스처 기반 권한 요청이 필요하다 → 코드 입력 직후 요청 흐름에 넣는다
- 임계값은 여기서 확정되지 않는다. phase4 실기 플레이테스트로 다시 잡는다
- 판정 모듈이 게임 코드에 스며들기 시작하면 즉시 되돌린다 (PROJECT.md §11)
