# Phase 1 — 렌더링 예산 확정

> 참조: PROJECT.md §2 렌더링 제약, §9-1, §12

## 전제

**조카 집 TV에서 30fps 안정 유지는 가능한 것으로 판단한다.**
성능 실측을 앞단의 차단 조건으로 두지 않는다. PROJECT.md §2의 제약(2D Canvas, 720p, 블러·그림자·대량 파티클 금지)을 그대로 예산으로 채택하고 바로 개발에 들어간다.

`tv-bench.html`은 **선택 작업**으로 남긴다. phase4 실기 방문 때 곁다리로 한 번 돌려 전제가 맞는지 확인하는 용도이며, 결과가 나오지 않아도 이후 단계는 진행한다.

## 목표

이후 모든 연출이 지켜야 할 숫자를 문서 하나에 박아둔다.
추측을 없애는 게 아니라, **추측을 한 곳에 모아 나중에 한 번에 고칠 수 있게** 하는 단계다.

## 산출물

- `docs/render-budget.md` — 렌더링 예산 상수 표
- `js/config.js` — 위 예산을 코드 상수로. 게임 코드는 이 값만 참조한다
- (선택) `tv-bench.html` — 전제 검증용

## 작업 항목

### 예산 확정 (`docs/render-budget.md` + `js/config.js`)

- [x] 목표 프레임 **30fps** — 모든 움직임은 `deltaTime` 기반, 프레임 수 전제 금지
- [x] 캔버스 내부 해상도 **1280×720**, CSS로 확대
- [x] 프레임당 스프라이트 `drawImage` 상한 — 초기값을 상수로 정하고 넘으면 드랍하는 규칙
- [x] 알파 블렌딩 스프라이트 상한 (위와 별도, 더 낮게)
- [x] **`shadowBlur` / CSS `filter: blur` 사용 금지**
- [x] **대량 파티클 금지** — 코인 연출은 개수 제한 + 미리 그린 스프라이트 시퀀스
- [x] **Three.js·WebGL 사용 금지**
- [x] **안전영역 5%** — 오버스캔 대비. 모든 UI는 이 안쪽
- [x] 정지 배경은 1장, 스크롤 배경은 타일 반복
- [x] 반복 연출은 오프스크린 캔버스에 프리렌더 후 blit

### 문법 수준

- [x] ES 문법 수준 결정 — **기반 계층(`config.js`, `fps.js`)은 ES5.** 파일이 작아 비용이 없고, 기반이 파싱 실패하면 화면에 아무것도 안 나와 원인 파악조차 어렵다.
      게임 코드의 ES6 사용 가부는 `tv-bench_1.html`의 `ES6 파싱` 항목으로 판정한다
- [x] 빌드 단계 없음(바닐라 JS)이므로 문법 하향이 필요해지면 수작업 범위가 크다 → 모듈 경계를 얕게 유지

### 런타임 계측 (실측 대신 상시 감시)

- [x] TV 셸에 **fps 오버레이** — 쿼리스트링(`?fps=1`)으로 켜지는 토글
- [x] 프레임당 `drawImage` 호출 수 카운터
- [x] 예산 초과 시 콘솔이 아니라 **화면에 경고** (TV 브라우저는 개발자도구가 없다)
- [x] 이 계측을 phase3 게임 루프에 처음부터 심는다 — 나중에 붙이면 안 붙인다
      *`js/loop.js`가 `LP.fps.init/frameStart/frameEnd/draw`를 프레임마다 호출한다. 게임 코드는 관여하지 않는다*

### 선택 작업

- [x] `tv-bench.html` — 스프라이트 개수 스윕 + 진단 정보(`userAgent`, 해상도, `devicePixelRatio`) 표시
- [x] 오버스캔 테스트 패턴 — 가장자리 5% 눈금선. 안전영역 실측
- [ ] phase4 방문 시 5분 내로 돌리고 결과를 사진으로만 남긴다

## 완료 기준

- [x] `docs/render-budget.md`에 위 숫자가 전부 확정값으로 적혀 있다
- [x] `js/config.js`가 그 값을 상수로 노출하고, 게임 코드에 같은 숫자가 중복되지 않는다
- [x] fps 오버레이가 켜지고 실제 프레임 수를 표시한다

## 검증 방법

개발 PC 크롬에서 예산 상한만큼 스프라이트를 그려도 로직이 무너지지 않는지 확인.
**실기 검증은 phase4에서 게임과 함께 이뤄진다.** 이 단계는 숫자를 정하는 것까지가 범위.

## 리스크

- 전제가 틀려 실기에서 30fps가 안 나오면 → `js/config.js`의 상한을 낮추는 것으로 대응한다. 게임 로직은 손대지 않는다. 이를 위해 예산이 코드 한 곳에 모여 있어야 한다
- TV 브라우저는 개발자도구가 없다 → 모든 진단은 DOM에 그린다. `console.log` 의존 금지
- TV 브라우저 캐시가 강하다 → 파일명 버전 접미사(`_1`, `_2`) 규칙 준수 (PROJECT.md §11)
