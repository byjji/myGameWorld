# Phase 5 — 로프 클라이밍 + NPC 러버밴딩

> 참조: PROJECT.md §5-2, §6, §9-4

## 목표

두 번째 미니게임 + **NPC 경쟁 구조 도입.**
"앉았다 일어나면 올라간다"는 인과가 화면과 정확히 일치해야 한다.

러버밴딩 로직은 여기서 만들어 이후 해머·레이싱에서 재사용한다.

## 산출물

- `js/games/ropeclimb.js`
- `js/npc.js` — 러버밴딩 공통 모듈
- 4레인 로프 배경 + 캐릭터 등반 스프라이트

## 작업 항목

### 게임

- [x] 세로 스크롤. **4레인** — 주인공 + 마리오 · 공주 · 쿠파가 나란히 경주
      *사람이 먼저 자리를 잡고 남는 레인을 NPC가 채운다. 쿠파는 우선 배치 — 페이스메이커가
      없으면 경주가 성립하지 않는다. 사람이 넷이면 NPC는 없다*
- [x] **스쿼트 1회 = 한 칸 상승**
- [x] **로프 높이 = 스쿼트 25회 정도, 한 판 60~90초** (5세가 쉬지 않고 가능한 스쿼트는 20~30회)
      *시뮬레이션: 2.2초 주기로 오르면 55초. 목표보다 조금 짧다.
      실제 주기는 조카에게서만 나오므로 `HEIGHT`를 미리 올리지 않는다*
- [x] 리듬이 일정하면 콤보 가속
      *`COMBO_BONUS`는 작게(0.08) 잡았다. 콤보는 "리듬 타면 조금 이득"이지
      25회를 15회로 줄이는 장치가 아니다. 조카가 지치면 그때 키운다*
- [x] 로프에 코인 배치
- [x] 쿠파의 밥밥탄 투하 — **감점 대신 0.5초 정지**
      *가장 앞선 사람을 노린다. 떨어지는 동안 깜빡이는 것이 곧 예고다*
- [x] 정상에 깃발 + 도착 연출
- [x] 세로 스크롤 배경은 타일 반복으로 처리 (phase1 스프라이트 예산 내에서)
      *타일 blit 대신 **가로줄(fillRect)**로 그렸다. 스크롤 감각은 같은데 `drawImage`를
      한 번도 쓰지 않아 예산에 아예 잡히지 않는다. 실제 배경 에셋이 생기면 타일 blit으로 바꾼다*

### NPC (`npc.js`)

- [x] 플레이어의 **실시간 속도(초당 스쿼트 수)** 측정
      *`SpeedMeter`, 창 6초. 창을 짧게 잡으면 한 번 쉴 때 0으로 떨어져 NPC가 굳어 보인다*
- [x] NPC 속도 = 플레이어 속도의 80~90%
- [x] 남은 거리 20% 미만에서 추격 배수 상승
```js
npc.speed = player.speed * 0.85;
if (remaining < 0.2) npc.speed *= 1.15;   // 막판 추격
```
      *위 식을 그대로 기본 속도로 쓰되 **목표 거리와의 오차를 비례 보정으로 더했다.**
      배수만 쓰면 플레이어가 한 번 크게 앞섰을 때 영영 못 따라잡아 화면 밖으로 사라진다.
      100초 시뮬레이션에서 최대 간격: 꾸준할 때 0.25, 폭주할 때 0.35, 도중에 쉴 때 0.4 이내*
- [x] **쿠파를 페이스메이커로.** 조카보다 살짝 느리되 계속 따라붙게
- [x] **마지막 20% 구간에서 역전 연출** — 쿠파가 살짝 앞서다 막판에 따라잡히는 흐름
      *`leadAt()`: 출발은 나란히 → 중반 +6% 앞섬 → 75% 지점부터 줄어 골인 직전 -3%*
- [x] **꼴등 없음.** 완주하면 다 같이 골인 연출
- [x] 배수 상수를 한 곳에 모아둔다 — **코드 문제가 아니라 플레이테스트로 찾는 숫자**
      *`js/npc.js`의 `TUNE`. 게임 파일에는 배수가 하나도 없다*

## 완료 기준

아래는 **조카 앞에서만** 확인된다. 게임과 NPC는 다 만들었다.
NPC 균형은 시뮬레이션으로만 확인했다 — 시뮬레이션의 "플레이어"는 지치지 않는다.

- [ ] 조카가 25회 스쿼트를 끝까지 해낸다 (못 하면 높이를 줄인다)
- [ ] 한 판 60~90초 안에 끝난다
      *2.2초 주기 가정으로 55초. 조카의 실제 주기를 재서 `HEIGHT`를 맞춘다*
- [ ] 쿠파가 압도적으로 앞서거나 뒤처지지 않는다 — 항상 화면 안에 같이 있다
      *시뮬레이션에서는 최대 간격 0.4 이내로 유지. 사람 상대로는 실기에서*
- [ ] 실기에서 조카가 **이겼고**, 아슬아슬했다고 느꼈다
- [ ] 스쿼트 판정 오인식 거의 없음 (느린 왕복이라 점프보다 안정적이어야 정상)

## 검증 방법

- 배수 값을 0.80 / 0.85 / 0.90으로 바꿔가며 조카 표정을 본다. **숫자는 표정으로 정한다**
- 한 판 후 조카가 숨이 찬 정도를 기록 — phase6 이후 게임 순서 배치의 근거
- 스쿼트 25회가 너무 힘들면 콤보 가속 폭을 키워 실질 횟수를 줄인다

## 리스크

- 하체 부하가 줄넘기와 겹친다 → **줄넘기와 로프를 연달아 붙이지 않는다** (PROJECT.md §9). phase6 룰렛의 체력 가중치로 강제
- 스쿼트를 대충 하는(무릎만 살짝) 편법이 생기면 pitch 임계를 올리기 전에 연출로 유도한다
