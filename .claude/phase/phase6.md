# Phase 6 — 해머 피하기 + 미니게임 선택/룰렛

> 참조: PROJECT.md §5-3, §7 룰렛, §9-5

## 목표

세 번째 미니게임 + **미니게임 선택 화면.**
게임이 3개가 되는 시점이라 "무엇을 할지 고르는 화면"이 여기서 필요해진다.

**phase6까지 끝나면 놀 수 있는 게임이 된다.** 조카에게 보여주고 반응을 본 뒤 나머지를 만든다.

## 산출물

- `js/games/hammer.js`
- TV 미니게임 선택 화면 + 룰렛 (`js/tv.js`의 `select` 화면, `GP.games.pool/roll`)
- `docs/playtest-2.md` — 3종 세션 플레이테스트 기록 **(빈 양식. 조카 반응 없이는 못 채운다)**

## 작업 항목

### 게임

- [x] 해머브라더스가 위에서 해머 투하, 아래에서 회피. 마리오1의 그 장면
- [x] **레인 3개.** 5개는 너무 많고 2개는 금방 질린다
- [x] `motion.js`의 좌우 기울기(절대 위치 매핑) 구독 — 임계 10~12도
      *`js/tuning.js`의 `TILT_LANE_DEG`(11도)·`TILT_RELEASE_DEG`(6도)를 그대로 쓴다*
- [x] **예고선 필수** — 낙하 0.8초 전 해당 레인 바닥이 빨갛게 깜빡. 없으면 반사신경 싸움이 된다
      *가까워질수록 빨리 깜빡인다. 남은 시간을 소리 없이 알려준다*
- [x] 속도는 **10초마다 계단식 상승.** 갑작스러운 가속 금지
      *1.70초 → 0.13초씩 → 0.80초가 하한*
- [x] 후반 **두 레인 동시 투하** — 나머지 한 곳으로 뛰어야 함. 이 게임의 하이라이트
      *22초 이후부터, 35% 확률*
- [x] **세 레인 전부 막는 패턴 절대 금지.** 패턴 생성기에 하드 가드로 넣는다
      *확률로 막지 않고 개수 자체를 `LANES - 1`로 자른다. 확률은 언젠가 반드시 터진다.
      시험에서 2만 번 + 난수를 최악으로 고정한 500번, 발생 0회*
- [x] 피격 시 게임오버 없음 — **0.5초 스턴 + 코인 소량 손실**
      *코인은 0 아래로 안 내려간다. 마이너스가 뜨는 순간 흥미를 잃는다 (PROJECT.md 10장)*
- [x] 점수 = 버틴 시간
- [x] **코인 레인** — 일부러 특정 레인으로 갈 이유를 만든다. 움직임이 훨씬 활발해진다
- [x] 레인 이동은 즉시 순간이동이 아니라 짧은 보간 이동 (기울기 흔들림에 캐릭터가 떨지 않게 히스테리시스 적용)
      *판정은 레인 단위(정수)로 하고 그림만 미끄러진다. 판정을 보간 위치로 하면
      "분명히 옆 칸에 있었는데 맞았다"가 생긴다*

### 미니게임 선택 / 룰렛

- [x] 미니게임 카드 나열 + 아래 룰렛 버튼
      *버튼은 없다. TV는 입력을 받지 않는다 (PROJECT.md 1장) — 폰을 흔드는 것이 버튼이다*
- [x] 룰렛 — 커서가 카드 사이를 빠르게 돌다 감속하며 정지
- [x] **폰을 흔들어 룰렛을 돌린다** (가능하면)
      *점프 판정을 흔들기로 쓴다. 12초 동안 아무도 안 흔들면 알아서 돈다 — 멈춘 화면이 제일 나쁘다*
- [x] 카드 직접 선택 시 즉시 시작
      *기울여서 카드를 가리키고 쳐올리면 그대로 시작. 어른용 갈래다*
- [x] **직전 게임은 룰렛에서 제외**
- [x] **체력 가중치** — 직전이 하체 부하 높음(줄넘기·로프)이었으면 다음 룰렛에서 그 둘을 제외.
      겉으로는 랜덤이지만 힘든 게임이 연속으로 안 나온다
      *게임 정의에 `load: 'high'|'mid'|'low'`. 후보가 다 걸러지면 조건을 하나씩 푼다 —
      뽑을 것이 없어 멈추는 쪽이 더 나쁘다*
- [x] 기본은 룰렛, 직접 선택은 보조. 어른이 "이제 앉아서 하는 거 하자"고 개입할 여지를 남긴다
      *뽑히지 않는 카드는 어둡게 표시하되, 직접 고르는 것은 막지 않는다*
- [x] 선택 완료 → 동작 시연 → **캘리브레이션** → 카운트다운 순으로 연결
      *결과 화면에서 6초 뒤 다시 선택 화면으로 돌아온다. 세션이 여기서 이어진다*

## 완료 기준

- [x] 3종(줄넘기·로프·해머) 연속 세션이 처음부터 끝까지 굴러간다
      *개발 PC에서 확인. 룰렛이 로프를 뽑고 시연 → 캘리브레이션 → 카운트다운 → 플레이까지 이어졌다.
      조카 앞에서의 3판 연속은 실기에서*
- [x] 룰렛이 하체 부하 높은 게임을 연속으로 뽑지 않는다 (100회 시뮬레이션으로 확인)
      *100판에서 같은 게임 연속 0회, 힘든 게임 연속 0회*
- [ ] 예고선 덕에 5세가 실제로 피할 수 있다
      *예고 0.8초는 코드로 보장했다. 그 시간이면 충분한지는 조카만 안다*
- [ ] 두 레인 동시 투하 구간에서 조카가 활발하게 움직인다
- [x] 세 레인 전부 막히는 패턴이 한 번도 나오지 않는다 (패턴 생성기 단위 검증)
      *2만 번 + 난수 최악 고정 500번, 발생 0회. 확률이 아니라 개수를 잘라서 막았다*
- [ ] `docs/playtest-2.md` 작성 — **여기서 나머지 2종(블록깨기·레이싱)을 만들지 판단한다**
      *양식만 만들어 뒀다. 조카 반응 없이는 채울 수 없다*

## 검증 방법

- 패턴 생성기를 게임 없이 단독 실행해 수천 스텝 시뮬레이션, 3레인 동시 차단 발생 0회 확인
- 조카 플레이 중 좌우 이동 빈도를 세어 코인 레인이 실제로 유인 효과가 있는지 확인
- 3판 연속 후 지친 정도 기록 — 체력 가중치 조정 근거

## 리스크

- 기울기 임계값이 조카의 자세에 따라 흔들린다 → 게임마다 재보정하되 임계는 낮게(10~12도) 유지
- 카드 선택 화면이 글자 위주가 되기 쉽다 → **아이콘·색 중심.** 글자 최소화 (PROJECT.md §10)
